## 1. Scope and preservation

This Issue fills the existing `Bedroom.unity` scene with a real, coherent 3D
environment. It does **not** create a second bedroom scene and does not change
the game story or activities.

Preserved unchanged from Issues #007–#011:

- `SceneNames.cs`, `SceneLoader.cs`, `GameManager.cs` and their assembly.
- All six registered scenes, their names, GUIDs and Build Settings order.
- All MATLAB scripts, tests, exports and Issue #007–#010 documentation.
- The activity scenes (`ColorSorting`, `TasteSorting`, `MathActivity`, `Ending`)
  and the pre-existing `SampleScene`.
- The existing `Main Camera` and `Directional Light` objects (renamed nowhere;
  their names are asserted by the Issue #011 regression tests).

The only pre-existing object renamed is the template typo `Righr_Wall`, which
is now `Right_Wall`. Its transform and collider are unchanged.

`ProjectSettings/ProjectSettings.asset`, `ProjectAuditorSettings.asset` and
`QualitySettings.asset` were rewritten by Unity with LF endings during batch
runs and were normalised back to the repository's CRLF convention, so they have
no content change. `CleanMyRoom.slnx` was regenerated by Unity to include the two
new test assemblies.

The interior is a 20 m × 20 m square, floor at `y = 0`, ceiling at `y = 5`.

front-right corner toward the back-left, so all three activity stations are
visible without moving.

## 4. Materials, lighting and rendering

- 42 URP Lit materials in `Assets/Materials/Bedroom/`, all solid colours with
  tuned smoothness. No texture files exist in `Shared_Data/Textures`, so no
  textures were invented.
- `M_Window_Glass` uses URP transparent surface settings (SrcAlpha /
  OneMinusSrcAlpha, ZWrite off) with alpha 0.38.
- `M_Lamp_Shade` has an emissive term for the lamp and ceiling fixture glow.
- Warm ambient light (`AmbientMode.Flat`, RGB 0.58/0.60/0.64).
- `Directional Light`: warm white, intensity 1.35, rotation (42°, -125°, 0°),
  soft shadows — reads as afternoon sun entering the windows.
- `Light_Ceiling`: point light at (0, 4.55, 0), intensity 1.7, range 17, soft
  shadows. `Nightstand_Light`: warm point light, intensity 0.8, range 5.
- Main Camera: (6.6, 4.8, -7.4), FOV 62°, looking at (-1, 1.35, 2.6). Its
  name, tag and URP camera data are preserved.
- MeshCollider on the floor and BoxColliders on walls and major furniture;
  small props have no colliders, so they do not create invisible obstacles.

No post-processing volume was added: the project's existing URP settings are
retained, and the batchmode screenshots show no magenta missing-material or
black-frame failures.

## 5. MATLAB-generated assets used

The Issue #010 export is the source of the imported toy block; Issue #007 meshes
supply the ball and drum. No MATLAB source file and no existing export was
modified. The builder copies the files, so the originals remain authoritative.

| Source (repository root) | Unity asset | Use |
|---|---|---|
| `Shared_Data/Meshes/Issue010/Issue010_Box_Unity.obj` | `Assets/Models/MATLAB/Issue010/Issue010_Box_Unity.obj` | `PF_MatlabToyBlock.prefab` (4 blocks) and `MATLAB_DisplayBlock` |
| `Shared_Data/Meshes/Issue010/Issue010_Box_Unity.mtl` | same folder | `CleanMyRoom_box` Phong material imported with the OBJ |
| `Shared_Data/Meshes/sphere.obj` | `Assets/Models/MATLAB/Issue007/MATLAB_Sphere.obj` | `MATLAB_Ball` (yellow) |
| `Shared_Data/Meshes/cylinder.obj` | `Assets/Models/MATLAB/Issue007/MATLAB_Cylinder.obj` | `MATLAB_Drum` (red) |
| `Shared_Data/Meshes/cube.obj` | `Assets/Models/MATLAB/Issue007/MATLAB_Cube.obj` | Imported and verified, kept available for future decoration; not instantiated |

Import settings applied by the builder: `globalScale = 1`, cameras/lights off,
animations off, mesh compression off, `isReadable = false`. Materials are
imported only for the Issue #010 OBJ (it has an MTL). Issue #007 OBJs have no
materials, normals or MTL, so scene instances receive URP materials explicitly.

Axis handling follows `Documentation/Graphics/Projection_and_Geometry_Export.md`:

- The Issue #010 **Unity** variant is already remapped from MATLAB Z-up to Unity
  Y-up, so it is imported without rotation.
- Issue #007 meshes remain MATLAB Z-up, so `MATLAB_Ball` and `MATLAB_Drum` are
  rotated −90° about X. Placement computes the renderer bounds after rotation
  and scaling so each object rests on the floor rather than floating.

Unity's OBJ importer mirrors X (right-handed → left-handed). The builder recentres
the imported bounds, so the visible result is unaffected.

## 7. Navigation considerations

- The floor provides a continuous 20 × 20 m walking surface.
- Four walls plus a front-wall opening bound the room; the left-wall door is a
  visual entrance, and the front opening keeps every viewpoint inside the shell.
- Furniture is grouped around the perimeter and the centre, leaving a clear
  circulation ring. Five representative waypoints are asserted free of
  non-floor colliders by `NavigationWaypointsAreNotBlockedByFurniture`.
- No player controller, camera controller or activity interaction is added in
  this Issue, so navigation is verified geometrically (scene structure,
  collider bounds and clear waypoints) rather than by walking a character.
- The ceiling is a solid slab above `y = 5`; the camera stays at `y = 4.8`,
  below it, so there is no camera-in-ceiling clipping.

## 8. Responsibility distribution

This Issue is Unity presentation work only. MATLAB retains all computational,
graphics-algorithm, coordinate-mapping and validation responsibilities defined
in `AGENTS.md` §3 and §14; the imported meshes are the product of the MATLAB
geometry and export code from Issues #007 and #010. Unity places, scales and
lights those meshes and supplies the room, furniture, input-adjacent structure
and visual feedback, as assigned by `AGENTS.md` §4 and §7.

No educational answer is evaluated in this scene, and no TCP message type was
added.
